## 1. Purpose

Hayah-Pulse produces **three distinct concrete outputs** for judges, clinicians, and citizens.

| Output | Audience | Channel |
| --- | --- | --- |
| **A — Reason-for-Flag Decision Card** | Clinician / provider | EHR / Clinician Portal |
| **B — Transparency & Choice Ledger** | Parent / adult citizen | Mobile / WhatsApp simulator |
| **C — Public Health Command & Fairness Dashboard** | Regulator / health authority | Command dashboard |

---

## 2. Output A — Clinician “Reason-for-Flag” Decision Card

Displayed inside the physician consultation screen before a Well-Child or IFHAS visit.

### Required fields

| Field | Description | Example |
| --- | --- | --- |
| Patient selector context | Synthetic patient identity | Name, age, sex, household_id |
| Pathway recommendation | Approved track + focus | `Priority IFHAS Cardiometabolic + Early HbA1c Panel` or `18-Month Well-Child + Targeted Speech/Developmental Screen` |
| Risk tier | Stratification label | High / Medium / Baseline Onboarding |
| Top driving factors (3–5) | Auditable reasons | Care gap + family/genomic + trajectory |
| Data confidence badge | Completeness signal | High Confidence vs Low Confidence / Sparse Record |
| Household care-gap alert | Optional linked HH flag | Adult IFHAS also overdue |
| Clinical firewall notice | Mandatory disclaimer | See wording below |
| Approve Preventive Order | One-click action (prototype) | Triggers simulated order approval |

### Example driving factors

1. **Care Gap:** Missed 18-month developmental visit (overdue by 64 days).
2. **Family / Genomic Context:** First-degree family history of early-onset Type 2 diabetes + actionable metabolic risk marker.
3. **Trajectory Drift:** Upward shift in pediatric weight-for-length percentile across last two visits.

### Confidence badge copy

- **High Confidence:** e.g. `High Confidence (48 months longitudinal EHR + consented genomic report)`
- **Low Confidence:** e.g. `Low Confidence / Sparse Record (Trigger Baseline Intake)`

### Clinical firewall notice (exact)

> Population outreach prioritization only — diagnostic orders require clinician confirmation under DoH guidelines.

## 3. Output B — Family “Transparency & Choice Ledger”

Sent to parents or adults in preferred language instead of generic SMS blasts.

### Required sections

#### Why You Are Receiving This

Plain-language reason, e.g.:

> Your child, Zayed, is due for his 18-month developmental check, and your family profile shows an opportunity for early metabolic wellness guidance.

#### Data Used (Full Visibility)

- List exact authorized sources (e.g. Past pediatric clinic visits, Consented Newborn/Family Wellness profile).
- Explicitly confirm what was **not** accessed (e.g. Insurance claims, non-health records).

#### Your Meaningful Choices

- **Care format:** `[Book Primary Care Clinic]` | `[Request Home Nurse Visit]` | `[Start with Tele-Consultation]`
- **Household bundle option:** e.g. `Your own IFHAS adult checkup is also due—book both in the same clinic visit?`
- **Privacy control:** `[Manage Predictive Outreach Preferences]` — one-tap opt-out without affecting standard care.

### Language requirements (prototype)

- Minimum: **Arabic** and **English** side-by-side or toggle.
- Persona framing: parent vs adult self vs elder caregiver as applicable.
- Preferred languages in data model also include Urdu and Tagalog (templates may stub beyond AR/EN).

## 4. Output C — Public Health Command & Fairness Dashboard

Used by health authority leaders to monitor equity, safety, and real-world impact.

### Required panels

| Panel | Content |
| --- | --- |
| Conversion funnel | Flagged High-Need → Invited → Booked → Visit Completed → Follow-Up Resolved |
| Segment parity matrix | Recommendation rates, FPR, FNR, attendance by age, sex, district, resident segment |
| Small-cell shield | Any cell with `n < 10` masked as `<10 — Suppressed for Privacy` |
| Outcome summary | Completed Well-Child / IFHAS actions; recall completion (synthetic) |

### Small-cell suppression copy (exact)

> `<10 — Suppressed for Privacy`

---

## 5. Cross-cutting UX rules

1. No black-box single score without reasons.
2. Uncertainty must be visible (badge / onboarding route).
3. Opt-out of predictive outreach must not block standard guideline care messaging in copy.
4. All screens use synthetic identities only; watermark or footer: `Synthetic demo data — not real patients`.
5. Screen acceptance criteria and component map: [v0.7-prototype-screens-spec.md](./v0.7-prototype-screens-spec.md).
