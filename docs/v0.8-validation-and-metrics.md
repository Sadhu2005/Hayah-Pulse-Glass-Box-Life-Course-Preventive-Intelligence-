## 1. Goal

Run a **synthetic validation & stress test** on the 500-resident cohort and produce an evaluation artifact that supports demo claims:

1. Model calibration (predicted vs simulated actual risk)
2. Care-gap catch rate vs standard age-only rules
3. Zero privacy leaks on small cells (`n < 10`)

Output paths:

```
data/synthetic/evaluation_report.json
data/synthetic/evaluation_table.csv
```

Optional UI: surface a compact table or cards on Screen 3.

---

## 2. Evaluation table schema

| Metric | Definition | Pass criterion (prototype) |
| --- | --- | --- |
| `n_residents` | Cohort size | = 500 |
| `calibration_brier` | Brier score on held-out synthetic labels | Reported; lower is better |
| `calibration_slope` | Slope of predicted vs empirical risk (binned) | Prefer 0.90–1.10; document if outside |
| `caregap_catch_rate_hayah` | Share of true overdue cases flagged by Hayah-Pulse rules+model | ≥ age-only baseline |
| `caregap_catch_rate_age_only` | Share flagged by age/sex calendar only | Baseline comparator |
| `lift_vs_age_only` | `(hayah - age_only) / age_only` | &gt; 0 on synthetic overdue set |
| `uncertainty_abstain_rate` | Share routed to Baseline Onboarding via uncertainty gate | &gt; 0; matches sparse segment |
| `small_cell_leak_count` | Number of displayed aggregate cells with raw `n < 10` | **Must be 0** |
| `reasons_coverage` | Share of flagged residents with ≥3 reasons | = 1.0 for flagged (non-onboarding optional ≥3) |

## 3. Calibration method

1. Use synthetic `elevated_preventive_need` labels from v0.6.
2. On a held-out split, compute calibrated probabilities.
3. Bin predictions (e.g. 10 bins); plot/store reliability points.
4. Fit calibration slope/intercept; store in report.

---

## 4. Care-gap catch rate vs age-only

### Age-only baseline (simplified)

- Child: invite if age hits milestone birthday window only (ignore overdue days, family hx, trends).
- Adult: invite if age band eligible for IFHAS calendar only.

### Hayah-Pulse

- Rules + risk tier + uncertainty routing as specified in v0.6.

### True positives for this test

Synthetic residents with `milestone_overdue_days > 30` OR `ifhas_overdue_days > 30` OR generative elevated-need label (document which definition is used in `evaluation_report.json`).

---

## 5. Small-cell privacy stress test

1. Build crosstabs used by Screen 3 (e.g. district × segment, sex × age_band).
2. Apply suppressor: if cell `n < 10`, replace count/rate with `<10 — Suppressed for Privacy`.
3. Assert no raw numeric `n` for suppressed cells is present in API payloads consumed by the fairness UI.
4. `small_cell_leak_count` must be **0**.
